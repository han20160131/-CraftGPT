# Minecraft AI Studio — 專案方向與介面規格

> 狀態：規劃中。本文記錄已確認的產品方向，不代表功能已實作。

## 1. 專案目標

Minecraft AI Studio 是一個以對話為核心的 Minecraft 模組創作工作區。使用者透過自然語言描述想法，逐步討論並製作遊戲資產、模組檔案與相關程式碼。初期以網頁版為主，並以 Google AI Studio 作為主要的 AI 輔助開發工具。

## 2. 核心介面

介面以 ChatGPT 的簡潔聊天體驗為參考，採用深色主題與三欄式工作區：

- **左側：專案與聊天清單**
  - 可新增專案。
  - 專案像資料夾一樣，可展開或收合。
  - 每個專案可以新增多個聊天。
  - 每個聊天保留自己的對話紀錄。
- **中間：聊天工作區**
  - 主要用於與 AI 討論和修改目前專案。
  - 保持簡潔，不放置多餘的首頁卡片或複雜儀表板。
  - 不提供「選擇模型」功能，也不顯示模型選擇器。
- **右側：專案檔案樹**
  - 顯示目前專案的資料夾與檔案。
  - 可供瀏覽和管理程式碼、貼圖、模型、音效、設定及文件。
  - 提供清楚可見的「匯入」與「匯出」按鈕。

## 3. 專案與聊天的關係

專案是容器，聊天是專案內的獨立討論串。

- 一個專案可以包含許多聊天。
- 新增聊天時，聊天必須建立在目前選取的專案之下。
- 切換聊天不應意外切換專案。
- 同一專案內的聊天可以依照權限與產品設計共用專案檔案和專案規格。
- 聊天紀錄屬於各自的聊天；專案規格與資產則屬於整個專案。

## 4. 檔案匯入與匯出

### 匯入

- 檔案樹上方提供「匯入」按鈕。
- 使用者可以匯入其他人製作的 Minecraft 模組或相關專案檔案，放進目前專案中繼續查看、討論與修改。
- 匯入前應辨識檔案格式，並顯示可能的衝突或不支援項目。
- 不應未經使用者確認就覆蓋現有檔案。
- 匯入的檔案應視為不受信任的外部內容；分析前不執行其中的程式或腳本。

### 匯出

- 檔案樹上方提供「匯出」按鈕。
- **匯出由使用者自行觸發**，不自動下載、不在背景擅自匯出。
- 匯出時應讓使用者清楚知道匯出內容與檔案格式。
- 目標是讓使用者取得可保存、分享或用於遊戲開發的模組專案檔案。

## 5. Minecraft 資產規則

必須清楚區分以下三種資產，不能混為一談：

1. **概念圖**：用於討論外觀與設計方向，可以較具藝術性。
2. **遊戲用 2D 貼圖 PNG**：應符合 Minecraft 的像素風格；武器物品貼圖應是平面圖像，通常使用透明背景，避免宣傳插畫式構圖、過度光暈或大量粒子效果。實際尺寸依資產用途而定，不應一律假設固定尺寸。
3. **3D 模型**：獨立的立體資產，應搭配適當模型格式及貼圖，不能把概念圖直接當成模型。

產生圖片時，必須標明它是概念圖還是可供遊戲資產流程使用的貼圖。若尚未達到可用規格，不可宣稱它已可直接放入模組。

## 6. 平台方向

- 規劃支援 Minecraft Java 版與 Bedrock 版。
- 兩個平台的模組格式、資產結構和功能能力不同；建立或匯入專案時應明確記錄目標平台。
- 不可假設同一份模組檔案能直接同時適用於兩個平台。

## 7. 設計原則

- 簡潔優先：主要工作區就是聊天與檔案樹。
- 不擅自替使用者產生 ZIP 或其他匯出檔。
- 不在使用者尚未要求開發前，擅自開始實作。
- 先確認規格，再規劃實作。
- 專案檔案、規格文件與聊天紀錄的歸屬要清楚。
- 不把示意圖、概念圖或模擬結果說成已實作功能。

## 8. 尚待討論

- 匯入要優先支援哪些封裝格式與專案結構。
- 匯出時是否提供整個專案、選取資料夾或單一檔案等選項。
- 匯入檔案與現有檔案發生衝突時，具體如何呈現差異及確認流程。
- Java 版與 Bedrock 版各自的第一階段支援範圍。
- 專案檔案樹中哪些檔案可以預覽、編輯或由 AI 修改。
